Submissions happen on the program's own pages: open **Projects**, create your
project with its name, description, code URL and live or demo link, link the
Hackatime projects you tracked time in, and hit **Submit for review**.

This page is what to have ready before you start filling that in.

## The two rules that are pass or fail

- **It has to be futuristic.** Whichever future — yours, the one we were
  promised, the one that never arrived — the project has to read as coming *from*
  a future.
- **The word "future" has to appear in it.** In the project name, the interface,
  the README. Somewhere a reviewer will see without hunting for it.

The second one sounds like a formality. It gets projects sent back, so do it
first.

## The rest of the checklist

- **Open source.** Public GitHub repo, a `LICENSE` file, and a README with images.
- **Something a reviewer can open.** A live link for software and websites; for
  hardware, schematics, photos and a build video — see
  [Hardware and electronics](/future/hardware).
- **Hours tracked in Hackatime**, on the projects you link to the submission.
- **Your own work.** At most 30% AI-assisted, no AI-generated text or images, and
  not a tutorial followed step for step.

## Before you submit, in this order

1. **Search your own repo for the word "future".** Ten seconds; it's the cheapest
   rejection to avoid.
2. **Clone it fresh and run it.** In `/tmp`, with no cached env and no local
   database. This catches the file you never committed.
3. **Open your live link in a private window.** Free hosting that fell asleep
   three weeks ago looks identical to a broken project from outside.
4. **Read your README as a stranger.** Does it say what this is and which future
   it's from, in the first sentence? Are there images?
5. **Check your Hackatime projects are linked** — by the names Hackatime knows,
   not the repo name, if those differ.
6. **Check the header.** If it says the round is closed, submissions aren't being
   accepted; ask in the channel about what's next.

## What happens next

A reviewer opens your links and runs down [the same checks](/future/review).
Turnaround is usually a few days and varies with how busy the program is. You'll
see the status change on your project or devlog once it's been looked at.

If something's missing, it comes back with notes. That's normal — fix it and
resubmit.

> [!TIP]
> Submit before the last day. Notes that arrive on the final afternoon leave you
> no time; the same notes a week out cost you an hour.
